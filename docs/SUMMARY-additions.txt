2. 音の流れ(最終形)
====================================================================
 入力(最大4) → [入力ごとのエフェクト] → 録音へ(「録音に反映」がオンのときだけエフェクト後の音)
                                    → 出力ごとの送り(オンオフ・dB) → 出力ごとのミックス → 全体音量
                                       → [出力ごとのエフェクト] → ±1に切り詰め → 再生デバイス
 入力ごとのエフェクトの順: ノイズゲート → ローカット → グラフィックEQ → パラメトリックEQ → エコー → リバーブ
 出力ごとのエフェクトの順: (全体音量) → ローカット → グラフィックEQ → パラメトリックEQ → リミッター
 録音は出力から独立していて、出力側のトラブル(デバイスを抜く・開けない)で録音は止まらない。録音を開始・終了しても、出力は途切れない(入力を開き直さずに引き継ぐ。5章)。出力が無効のときは追加の処理をしない。
 無音分割・自動開始の判定は、エフェクトをかける前の音(DryPeak)で行う。ゲートなどを入れても録音の動作は変わらない。

3. 段階ごとの仕様・工夫・注意点
====================================================================
[段階1 ミキサー(Core/Routing.cs の MixBus)]
 - 入力を「送り(オンオフ・音量)」に従って足し、全体音量をかけ、±1に切り詰める。録音のミックスと出力ごとのミックスで同じ計算を共用。
 - 置き換え前の計算とビット一致(108通りの組み合わせで確認)。録音の音が変わらないことを保証するため。
 - 段階5で、全体音量のあと・切り詰めの前に呼ぶフック(post)を追加。リミッターが効く前にハードクリップされないようにするため。

[段階2 出力デバイスと時計ズレ補正(Core/OutputRenderer.cs, Audio/OutputDevice.cs)]
 - 再生デバイスは自分のクロックを持つので、録音側とずれていく。出力側のコールバックで「引っ張る」方式にして、入力ごとのバッファから取り出す。
 - 入力ごとにタップ(複製先)を持ち、微調整できるリサンプラ(StreamResampler の Trim)で変換比を ±0.5% の範囲で調整。
   たまり量の目標は50ms。PI制御(Kp 0.1 / Ki 0.01)。不足したら無音を出して再びためる。250ms を超えたら古い分を捨てて目標に戻す。
 - 出力は録音エンジンの遅延(約0.3秒)を通らない。遅延の目安は約110ms。出力ごとに遅延が違う。
 - ループ防止: 入力として取り込み中のデバイスは出力先に選べない(DeviceCatalog.IsLoopCombination)。既定の再生デバイスのIDは3秒キャッシュ。
 - 落とし穴: NAudio の SampleToWaveProvider は byte[] を float[] として渡す。Array.Copy / Array.Clear が ArrayTypeMismatchException になり、
   出力が無音になった(CABLE宛の無音の原因)。作業用の配列に書いて、1サンプルずつコピーして解決。
 - 診断表示(呼出回数・アンダーラン・たまり・エラー)を出力カードに入れてある。不具合の切り分け用。

[段階3 複数出力・出力ウィンドウ・入力名(App/OutputWindow.cs, MainWindow.Output.cs)]
 - 出力は最大4。カードは最初1枚(ミックス1)。新規カードの出力先は「未選択」で停止状態から始まる(既定のスピーカーを自動で選ぶと、PC内部音の入力と回り込むため)。
 - カード: 名前(12文字まで)/ 状態 / FX / ✕(削除は確認ダイアログ、既定=いいえ)/ 出力先 / 「出力する」/ 全体音量 / メーター / エラー / 入力の一覧(畳める。畳んだ状態は出力ごとに記憶)。
 - 狭いときはカードを折り返す。出力ウィンドウを閉じても出力は止まらない。メイン画面と通知領域に「🔊 出力中」を表示。
 - 入力名: メイン画面の「入力1〜4」をダブルクリック/右クリックで変更。1つの名前をメイン画面・出力ウィンドウ・エフェクトで共通に使う。
 - Bluetoothヘッドホン: デバイスのMixFormat(共有モードの形式)をそのまま使う。float固定で開くと 0x80070057 で拒否される。16/24/32bit整数にも対応。
   開けなかったときは、イベント/ポーリングとバッファ長を変えて最大5通り再試行し、エラー文に形式と方式を表示。
 - 出力ウィンドウを開くときは、先に暗い「読み込み中」画面を出し、デバイス一覧は別スレッドで取得(白い画面で固まって見える問題の対策)。一覧は10秒キャッシュ。
 - 🔊ボタン: クリックでメニュー(出力ごとのオン/オフ・すべて停止・すべて再開・出力ウィンドウを開く)。ダブルクリックで出力ウィンドウ。
   メニューは、ダブルクリックでないと分かるまで0.3秒待ってから出す(待たずに出すと2回目のクリックがメニューに吸われるため)。
 - プリセット読み込み時は、動作中の出力をすべて止める(プリセットに合わせて出力先が変わるため)。

[段階4 入力ごとのエフェクト(Core/Effects.cs, App/EffectWindow.cs, MainWindow.Fx.cs)]
 - 開き方: メーターのダブルクリック / FXボタン / 右クリックメニュー。パネルは1枚だけ開き、上の入力切り替えで他の入力に移る。設定のコピー・貼り付け(「反映先」は貼らない)、すべてバイパス。
 - タブ: 「イコライザ」「ノイズゲート」「エコー・リバーブ」。見出しに、かかっているものの内訳(● グラフィック・ローカット など)を表示。バイパス中は○。
 - 反映先: 「録音に反映」(既定オフ=録音は素の音)/「出力に反映」(既定オン)。
 - グラフィックEQ: 10バンド(31/62/125/250/500/1k/2k/4k/8k/16kHz)、各±12dB、Q 1.41。ドラッグ・ダブルクリックで0dB・ホイールで±0.5dB。10種の初期設定付き。
   周波数カーブは設定から計算して描く(実際の音の測定と一致することをテストで確認)。常に表示され、ローカット・パラメトリックの変化も同じ曲線に反映される。
   グラフィックだけオフのときは、曲線から帯域分を除き、つまみだけ薄くする。
 - ローカット: 20〜400Hz、12dB/oct、0=なし。独立した行(パラメトリックと混ざらない)。
 - パラメトリックEQ: 4バンド。周波数20Hz〜20kHz、ゲイン±12dB、幅Q 0.3〜8。グラフィックと同時に使える(順番はグラフィック→パラメトリック)。
 - ノイズゲート(最初にかかる): しきい値-70〜-10dB(既定-45)、戻り20〜1000ms(既定200)、下げる量6〜80dB(既定40)。
   全チャンネルの最大値で判定して左右連動。開く3ms。開くしきい値より4dB低い値を下回って60ms続いたら閉じる(バタつき防止)。
   使い方: メーターで、ノイズだけのときの位置より少し上にしきい値を合わせる。語尾が切れるときはしきい値を下げるか戻り時間を長くする。
 - エコー: 間隔20〜1000ms、くり返し0〜0.9、量0〜1。リバーブ: Freeverb(コム8+オールパス4、左右23サンプルずらし)。部屋の広さ・こもり・量。
 - 実装の工夫: 設定は「読み取り専用のコピー」を丸ごと差し替える方式(音のスレッドとの競合を避ける)。何もかけない設定のときは配列に一切触れない(ビット一致)。
   入力は録音用とは別のスレッド/別のチェーンを持つので、出力ごとに別のインスタンスでかかる。
 - 文字は12.5px(エフェクト画面)。ウィンドウ幅は620、画面に収まらないときはスクロール。

[段階5 出力ごとのエフェクト(Core/OutputFx.cs, App/OutputFxWindow.cs)]
 - 出力カードのFXボタン(かかっていると「FX ●」、バイパス中は「FX ○」)から専用ウィンドウ。出力ごとに別々の設定。
 - 内容: ローカット / グラフィックEQ(曲線は常に表示)/ パラメトリックEQ / リミッター(上限-24〜0dB・既定-1dB、戻り20〜1000ms・既定150ms)/ すべてバイパス。
 - リミッターは1.5ms先読み。「必要なゲインの最小値フィルタ」+「移動平均」で、出力が上限を超えないことを数式で保証(テストでも確認)。
   左右連動で音の定位が動かない。遅延はその出力だけ1.5ms(録音には影響しない)。
 - 保存: カードごとに Output{n}Fx* として ini に、プリセットの JSON にも入る。初期設定のままなら ini に書かない。

[段階6 VST(調査のみ)]
 - 結論: VST3 SDK は 3.8 から MIT で、ライセンス上は問題ない。アプリ内で直接読み込むと、プラグインの異常終了で録音ごと落ちる(.NETはメモリアクセス違反を捕まえられない)。
   別プロセスのヘルパーexe+共有メモリ方式を推奨。ヘルパー側で NAudio.Vst3 を使えば、本体は NAudio 2.2.1 のままでよい。
 - 本体のNAudio 3への移行は不要と判断(NAudio 3 は .NET 9 以上が必須で、音声バッファのインターフェースが Span 方式に変わるため、自作部分の書き換えが必要)。
 - 実装は大がかりなので保留中。再開するときの材料は docs/INVESTIGATION-vst.txt に全部ある。

4b. 録音開始・終了での出力の途切れの修正(11/9。RecorderController / Core/SourceReuse.cs)
====================================================================
 - 問題: 以前は、録音を始めるたびに入力デバイスを閉じて開き直していた(取り込み用バッファを空から始めるため)。出力は入力の取り込みの上に乗っているので、
   一緒に切れ、約0.5秒途切れた。録音終了時も同様。
 - 修正: 開いている入力が「入力の枠・デバイス・サンプルレート・チャンネル数がプリセットと同じ、かつすべて接続中」なら、開き直さずに引き継ぐ(SourceReuse.CanReuse)。
   * 録音開始時: 入力ゲインをプリセットに合わせ、取り込み用バッファを Clear する。録音前にたまっていた古い音を録音の先頭に混ぜないため。
     出力用のタップ(出力ごとの複製バッファ)には触れないので、出力は途切れない。
   * 録音終了時: モニターか出力が必要なら入力を閉じずに残し、画面側の StartMonitor がモニターの状態だけ作り直す(StartMonitor は「モニターが動いていない・入力が開いたまま」のときだけ引き継ぐ)。
   * 条件が合わないとき(デバイス・形式の変更、つながっていない入力がある)は、従来どおり開き直す。この場合は出力が一瞬途切れる。
   * 入力確認の再起動(デバイスや形式を変えたとき)は、従来どおり開き直す。
 - 確認用: 引き継いだときは画面のログに「入力を開き直さず引き継ぎました(録音前にたまっていた音 n ms は破棄)」と出る。
 - 注意: 録音の開始・終了の経路に関わる変更なので、今後ここを触るときは、出力なしの通常の録音、デバイスの抜き差しからの復帰、録音先頭に古い音が混ざらないこと、を必ず実機で確認する。

5. 技術的な注意点(次に触る人へ)
====================================================================
 - WPFの画面部分(App)はLinuxではビルドできない。GitHub Actions でのみ確認でき、見た目は実機確認が必要。Core のロジックは自己テスト(Linux)で確認。
 - build.yml: docs/・*.md・*.txt だけの変更ではビルドしない。ビルド成功後に古いArtifactを削除し、直近2件だけ残す。
 - 出力デバイス: MixFormat のまま開く。float かどうかは GUID を直接比較(NAudio の定数に依存しない)。
 - 出力ごとの設定オブジェクトは「参照」で管理(同じ内容の別カードを区別するため)。カード削除・プリセット切替時は、そのカードのFXウィンドウも閉じる。
 - 出力が失敗した場合(デバイスが外れた等)は、5秒ごとに自動で再試行する。録音は止まらない。
 - エフェクトは「録音に反映」がオフなら録音に一切影響しない。「録音に反映」をオンにすると、波形表示もエフェクト後の音になる。
