■ 目的
 コード中の日本語を「キー=文」の組に置き換え、テキストエディタで直せるようにする。多言語(en.ini)は同じ仕組みの上に後から載せる。
 最優先: 画面・動作を変えない(見た目と動作は今と同じ)。録音の経路には触れない。

■ 規模の見積り(2026-11-27 時点の調査)
 - コード: Core 109行 / Audio 42行 / App 322行に日本語の文字列。補間文字列($"…{x}…")は約70行。
 - XAML: 1ファイル(MainWindow.xaml)に Content/Text/Header/ToolTip/Title の日本語が137か所。
 - 多い順: MainWindow.Settings.cs 51 / MainWindow.xaml.cs 40 / EffectWindow.cs 39 / MainWindow.Files.cs 33 / AppInfoWindow.cs 33 / Models.cs 31 / RecorderController.cs 28 / OutputWindow.cs 28。
 - 合計およそ 600 か所前後(キー数は 450〜550 見込み。同じ文言はキーを共用)。

■ 仕組み(設計)
 1. Core/Loc.cs(OS非依存・自己テスト可能): Loc.Get("キー") / Loc.Get("キー", 引数…)(string.Format 方式 {0}{1})。キーが見つからないときは「キー名そのもの」を返す(落とさない。画面でキーが見えたら漏れと分かる)。
 2. 文言の置き場: Lang/ja.ini。UTF-8、`キー=文`、`;` で始まる行はコメント、改行は `\n`。区分は `[main]` `[output]` `[fx]` `[err]` のように画面・機能ごと。キーは `main.record.start` の形。
 3. XAML: `{ui:T キー}`(MarkupExtension)。コード: `Loc.Get("キー")`。
 4. 読み込み: (推奨)ja.ini を exe に埋め込み(リソース)、exe と同じ場所に `Lang\ja.ini` があればそれを優先(テキストエディタで直す用)。埋め込みなので、ファイルが無い・壊れていても落ちない。配布物の直下を増やさない。
 5. 外出ししないもの: 保存される値(ini/JSON に書かれる文字列)、ファイル名テンプレートの変数名({Date}等)、ログの技術的な英語、コメント、自己テストの検査文。
    保存される日本語の既定名(例: 出力「ミックス1」、入力名)は、言語を変えても保存値が変わらないよう「表示用」と「保存値」を分ける(英語化の段階で扱う。日本語だけのうちは現状維持)。
 6. 自己テスト(Linux・Actions で毎回): ①XAML/コードが使う全キーが ja.ini にある ②ja.ini に重複キーがない ③ja.ini にあるが使われていないキーがない(警告) ④{0}{1} の個数が使用側と一致 ⑤ソースに日本語の文字列リテラルが残っていない(外出し済みの範囲だけ。段階ごとに対象を広げる)。
 7. 文体(ユーザー決定 11/27): 体言止め中心。例「録音開始」「保存失敗」「確認が必要」。です・ます調にしない。話し言葉・命令文を避ける。文言は移す時に同時に直す(二度手間を避けるため)。

■ 想定される問題と対策
 - キーの付け間違い・抜け → 自己テスト①で検出(画面でキー名が見えるだけで落ちない)。
 - 引数({0})の個数の違い → テスト④。
 - XAML の MarkupExtension がデザイン時に失敗 → ビルドはActionsだけなので影響は実行時のみ。段階0の見本で実機確認してから広げる。
